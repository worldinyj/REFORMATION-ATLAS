## 2. AI Studio Build에 실제로 적용하는 순서

기존 AI Studio 앱의 **비공개 복사본 또는 별도 스테이징 프로젝트**에서 진행한다. 앱을 다시 생성하거나 현재 디자인·라우팅·데이터를 덮어쓰지 않는다.

1. 위 JSON과 JS 두 파일을 V4.29 GitHub 연구 브랜치에서 내려받아 현재 앱의 스테이징 소스에 추가한다.
2. 먼저 **서버/호스팅 수준 인증과 권한 검사**를 설정한다. 앱에 공개 금지 문구나 noindex를 넣는 것만으로 비공개가 되지는 않는다. GitHub 저장소가 공개라면 이 연구 파일 자체는 별도 비공개 자산이 아니다.
3. 아래의 **한 번짜리 AI Studio Build 통합 프롬프트**를 적용한다. JSON의 역사 내용을 다시 작성하도록 지시하지 않는다.
4. 스테이징에서 8권 진입, 여섯 주제→7개 역사권 이동, 6개 입문 장면, 로컬 검색을 직접 검증한다.
5. 실제 앱에서 독자 테스트·전문가 교열·권리 검토·명시적 승인 없이 공개 배포하거나 main에 병합하지 않는다.

## 4. 코드 적용 예시 — 도구나 프레임워크를 강제하지 않음

```js
import payload from './V429_L0_PRIVATE_STAGING_CONTENT.json';
import { createPrivateAtlasNavigator } from './atlas_private_staging_adapter.mjs';

const atlas = createPrivateAtlasNavigator(payload);
const volumes = atlas.resolve('/atlas-preview/volumes');
const theme = atlas.resolve('/atlas-preview/themes/T415-01');
const matches = atlas.search('후스');
// 반드시 서버측 인증을 통과한 비공개 환경에서만 렌더링한다.
```

위 경로는 **제안한 내부 라우트 규약**이며 현재 배포 중인 앱 URL이라고 주장하지 않는다. 실제 앱의 라우터가 다르면 기존 라우트와 충돌하지 않게 매핑한다. 자체 텍스트라도 Markdown에 raw HTML 실행을 허용해서는 안 된다.

V4.28 오프라인 미리보기는 Chromium과 WebKit에서 각각 236개 자동 검사를 통과했다. **새로운 AI Studio 앱의 실제 통합·디자인·실사용 검증이 통과했다는 뜻은 아니다.** 현재 `can_ship=false`다.
