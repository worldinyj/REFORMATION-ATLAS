## AI Studio Build에서 사용할 세 가지 화면

| 경로의 논리적 종류 | 데이터 | 독자가 하는 일 | 주의점 |
|---|---|---|---|
| `VOLUME` | `volumes[]` | 8권 목록 → 1권 상세 원고 | VOL-08은 8번째 시대가 아니라 6주제 자료 아카이브 |
| `THEME` | `themes[]` | 6주제 목록 → 7개 역사권 비교 연결 | 앵커는 연구 ID를 토대로 한 논리적 연결, 실제 심층 아티클 URL 아님 |
| `CHAPTER` | `reader.chapters[]` | 입문 1~6장 순서대로 읽기 | 10분은 목표이지 실측이 아님 |

아직 웹앱에 없는 URL을 추정해서 만들지 않는다. 기존 AI Studio 앱의 라우팅을 살펴 해당 URL 표현에 `VOL-01`, `T415-01`, `INTRO-1` 같은 ID를 매핑해야 한다. 본문 데이터는 그대로 보존하고 마크다운 헤딩·단락·인용·강조만 안전하게 렌더링한다. 장면 이동이나 검색은 화면 기능이고, 편집 상태를 허위로 '심사완료'로 바꾸는 일이 아니다.

## 실제 적용 순서 (앱 소유자가 비공개 스테이징에서 실행)

첫째, 기존 Google AI Studio 앱을 복제하거나 테스트용 브랜치를 이용하고, 접근 통제가 작동하는 **비공개 미리보기**에서만 진행한다. GitHub 연구 브랜치에 파일을 저장했다는 사실만으로 AI Studio의 내부 접근 제한이 이루어지는 것은 아니다. 앱의 현재 폴더 구조나 연결 방식은 이 단계에서 실제로 확인되지 않았으므로 특정 소스 파일을 덮어쓰지 않는다.

둘째, GitHub에서 `handoff/V429_AI_STUDIO_PRIVATE_L0_CONTENT_IMPORT.json`을 내려받아 프로젝트에 수동으로 추가한다. AI Studio Build에 파일 첨부 기능이 있으면 첨부하고, 없으면 프로젝트의 콘텐츠 정적 데이터 파일로 복사한다. 공개 저장소의 raw URL을 운영 런타임에 매번 호출하지 않는다. 운영 중 자동 업데이트나 외부 네트워크 의존성도 아직 요구하지 않는다.

셋째, 네비게이션 '역사권 / 주제 / 입문 읽기'를 원래 앱의 디자인 시스템에 연결한다. 새로 도입되는 데이터의 편집 상태는 모두 **NOT_SIGNED_OFF**이며 앱 전체를 관통하는 공개 상태는 **BLOCKED**로 유지한다. 일반 독자 화면에는 내부 연구 claim ID나 원전 교감·평가 정답 메타데이터를 표시하지 않는다.

넷째, 비공개 스테이징에서 제목·본문·페이지 이동·모바일 320/375px 너비·키보드 초점·검색·본문 누락을 다시 확인한다. V4.28의 472개 PASS는 **독립 HTML 시제품에만 적용**되므로 별도 AI Studio 앱의 테스트를 대신하지 않는다.

## 반드시 거절해야 하는 두 가지 오해

**첫째, 'Chromium/WebKit 472개 PASS니까 AI Studio도 검증됨'은 틀리다.** 그 성적은 V4.28의 정적 HTML 단독 시험에 대한 것이다. AI Studio 앱에는 아직 임포트·실행·스크린샷·키보드 접근성 검증이 수행되지 않았다.

**둘째, '콘텐츠를 앱에서 읽을 수 있으니 역사·저작권 심사도 완료됨'은 틀리다.** 특정 교리의 판본과 비유럽 지역 연혁, 한국어 번역 서지는 별도로 전문가의 서면 검토를 받아야 한다. 특히 아우크스부르크 1530/1531/1540, 칼뱅 1536/1559/1560, 왈도파 1532 관련 세부 주장의 '보류'를 유지한다.
