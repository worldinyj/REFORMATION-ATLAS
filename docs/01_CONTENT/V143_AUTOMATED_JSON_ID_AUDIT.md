# V1.43 — 전 JSON 자동 ID 감사

**2026-10-30 · 연구 브랜치, 공개 불허**

### 구현
`scripts/audit_atlas_all_json_v143.py`는 매 실행 시 `data/**/*.json`을 자동 발견한다. 94개·117개와 같은 변하는 목록을 하드코딩하지 않는다. 잘못된 JSON 파싱, 세 종류 정본 참조(`person_id`, `document_id`, `event_id`)의 존재 여부, 위클리프→후스 『교회론』 오귀속, 후스 개인 저작으로 잘못 귀속된 1420년경 프라하 4개조를 탐지한다.

**실행:** `python3 scripts/audit_atlas_all_json_v143.py --root . --output audit-v143-local.json`. 문제 발견 시 비정상 종료 코드(1)를 반환한다. audit-v143-local.json은 로컬 실행 결과이며 원격 GitHub 실측 결과로 자동 간주하지 않는다.

### 실제 테스트와 미실행 구분
이 턴에서 별도 로컬 **인위적 3개 JSON 테스트 픽스처**를 만들고 감사 로직의 초기 구현을 실행해 위클리프/후스 오류를 탐지하는지 검사했다. 결과는 `WYCLIFFE_HUS_DE_ECCLESIA_MIXUP=1`, 종료 코드 1. 단, 테스트한 초기 구현과 GitHub에 게시한 경량 버전은 기능 구조가 유사하나 완전히 같은 파일 바이트가 아니다. GitHub 저장소 전체를 로컬 환경으로 내려받지 못했기 때문에 117개 JSON을 실제 전수 파싱·검증했다고 주장하지 않는다.

### 규칙의 한계
- `OV-*` 필드만 대상으로 한 보수적 구조 검사다. `*_ids` 배열, 인쇄판 `EDN-*`, 출처 `SRC-*`, 그래프 관계의 의미적 정확성은 검사하지 않는다.
- 같은 제목이더라도 원래 저자가 다른 저작은 별도 ID로 유지해야 한다.
- 내용의 역사학적 정확성과 16세기 사본 직접 교감은 여전히 사람이 검토해야 한다.
- `main`, Google AI Studio 앱, 기존 자료는 수정하지 않았다.

### 콘텐츠 개발과 병행할 작업
심화 원고는 검증된 인물·저작 관계만 사용해 웹앱으로 전달하고, 교파별 차이를 뉘앙스 있게 설명하며 출처 종류·판본·확실성 수준을 명시한다.
