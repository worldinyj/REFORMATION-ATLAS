# V1.65 REFORMATION-ATLAS 연구 데이터 통합 준비도 감사

**2026-10-31 — 연구 브랜치 전용. main 및 별도 Google AI Studio 개발 앱에는 적용하지 않음.**

## 결론: 참조 구조는 연결 가능, 정식 웹앱 반입은 보류

V1.53~V1.64의 독자용 콘텐츠·역사 지도·시각자료 권리·문헌 판본·근거 카드 사이의 계약을 하나의 검증 경로로 묶었다. 이것은 UI 구현이나 전체 역사 서술의 사실 검증이 완료됐다는 뜻이 아니다.

| 영역 | 점검 범위 | 현 상태 |
|---|---|---|
| 독자 콘텐츠 | V1.54 60개, V1.56 심층 페이지 10개 | 데이터 구조 검증, 학술 감수 대기 |
| 역사 지리 | 11개 도시와 읽기 페이지 참조 | 도시 대표 좌표. 역사 유적 정밀 좌표 아님 |
| 시각자료 | 후보 14개, 인물화 5개, 영인 4개 | 이미지 게시 승인 없음 |
| 문헌 비교 | 판본 5개, 비교행 6개 | 판본 ID 참조 검증, 원문 직접 교감 미완료 |
| 증거 경로 | 근거 카드 8개와 탐색 경로 8개 | 단계별 연결 및 증거 수준 검증 |
| AI Studio | 앱 내부 데이터 모델·UI | 본 세션에서 조회/수정하지 않음 |

## 필수 보류 조건 5개
1. **학술 감수**: 개요 수준의 2차 자료를 바탕으로 작성한 해설은 정확성·맥락·표현을 전문가가 확인해야 한다.
2. **초상·영인 이미지 권리**: 파일별 저작권 및 출처표시 검토를 마치기 전에는 실제 이미지 파일을 배포하지 않는다.
3. **원문 증거 교감**: 특정 문구의 판본 차이를 주장할 때 실제 판면·쪽수·장절을 직접 대조한다.
4. **정본 ID 조정**: Wycliffe의 임시 저작 ID 등과 기존 정본 ID의 대응을 독립 감사한 뒤 반입한다.
5. **앱 스키마 적합성**: 병렬 개발 중인 Google AI Studio 앱의 데이터 계약을 확인하기 전까지 연구 데이터의 필드 이름이 호환된다고 단정하지 않는다.

## 웹앱 소비 경로
독자 화면은 `reader → timeline/map → work → edition → claim → evidence`를 탐색할 수 있다. 모든 증거 카드에는 읽기 쉬운 역사적 해설과 출처 URL 및 원문 교감 여부가 따라와야 한다. 웹앱은 `can_ship=false`를 통과 불가 규칙으로 해석해야 하며, 이미지 권한에 대한 `false`를 단순한 누락값으로 취급해서는 안 된다.

## 검증 실행
`python3 scripts/validate_atlas_v165.py`를 실행하면 파일 존재·ID 참조·개수·권리 차단·지도 좌표 정밀도·증거의 원문 검증 보류 여부를 검사한다. 이전 버전별 검사와 전체 JSON 식별자 감사도 CI에서 수행한다.
