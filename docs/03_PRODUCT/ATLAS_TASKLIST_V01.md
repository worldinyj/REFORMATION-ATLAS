## 1. 우선 전략
1. **G0 결정:** 이미 만든 프로젝트 계획/PRD/TRD/UXUI의 잠정 선택사항을 사용자와 검토한다. 승인 전 배포나 공개 콘텐츠 이동 금지.

4. **G3 발견·연결:** 검색·관계·출처/검토 상태·빈 화면.
5. **G4 검증과 프리뷰:** 접근성·공개 누출 테스트·성능·사람 검수. 별도 명시적 승인만 실제 배포.

## 3. 구간별 완료 정의
### G0 (설계 승인)
- 기능 범위와 기술 스택/프리뷰 접근 방침 결정 기록이 있어야 한다.
- `TRD`의 Astro/Cloudflare 권장안은 **제안**일 뿐 사용자의 확정 선택이 아니다.
- 승인 전 앱 코드는 개발하지 않으며, 완료된 설계 초안과 진행 중인 코드를 혼동하지 않는다.

### G1 (데이터/게이트)
- 기존 8권·127 객체·32관계가 읽기 전용으로 어댑터에 연결되어야 한다.
- `OV-P`→기존 `PER` 3건에 관한 동일 인물 식별/리디렉트 테스트가 있어야 한다.
- 초기 `approved=false` 콘텐츠가 공개 HTML/JS/JSON/검색 인덱스/미디어 출력에 **0건**이어야 한다.
- `OVERVIEW`와 후속 `DEEP_RESEARCH` 깊이 블록은 콘텐츠 모델에서 구분.

### G2 (기초 화면)
- 권 8, 인물 33, 사건 34, 문헌 20, 주제 10, 텍스트 장소 22의 **내부 검토용 탐색**이 가능.
- 볼륨 8은 연대상 별도 시대가 아닌 통합 아카이브로 표시.
- 자료의 상태·원문 접근 등급·미검증 시각자료 안내를 제공.
- 추가 자료가 없어도 빈 상태 UI가 깨지지 않는다.

### G3 (관계와 검색)
- 검색은 별칭/한글·영문·라틴어 제목을 지원.
- 위클리프→후스 등의 영향 관계는 실물 만남으로 바뀌지 않는다.
- 교단·원전·역사 자료의 관점을 혼동하지 않도록 출처 링크/주의 고지.

### G4 (프리뷰/검증/공개 결정)
- 14개 화면·6개 사용자 흐름·PRD 수용시험 10묶음의 체크리스트.
- 모바일/키보드·WCAG 2.2 AA 지향 접근성 및 성능 목표 측정.
- 미승인 입력은 공개 `dist`에서 제외. GitHub 공개 브랜치의 자료 가시성도 별도 검토.
- 비공개 로컬 프리뷰 완료는 정식 운영 배포 승인이 아니다.

## 5. 테스트·의존성 관리
- `data/overview/tasklist_v01.json`은 기계 판독용 동일 데이터 정본이다.
- 모든 Task는 `NOT_STARTED`로 시작하며 임의로 `DONE`으로 변경하지 않는다.
- 테스트 기준은 각 Task의 `definition_of_done`과 `verification`; ‘코드 작성함’만으로 완료 판정하지 않음.
- 승인받은 릴리스 후보는 프로젝트 계획과 별도 승인 기록이 있어야 한다. 모든 DRAFT 연구 데이터가 승인 없이 외부 노출되면 안 된다.
- `P1` 작업은 초기 정적 사이트에서 확장성을 확보한 뒤 순서대로 수행한다.

## 6. 계획 외 선행 작업
- 기존 8권 개요 중 자료 부족: VOL-05 가톨릭 개혁의 다양한 시각, VOL-07 한국인 초기 번역자, VOL-08 판본별 문헌 구조.
- 장소 22개의 실제 위치와 역사적 현장에 관한 출처를 추가해 지도 정확도를 높이되, P0 개발은 기다릴 필요 없다.
- 이전 제3권의 상세 라틴·체코어 문헌 교감과 AI 그림 고증은 **독립 심층 연구 트랙**으로 계속 관리한다.

**최종 상태:** `TASKLIST_DRAFT_READY`, `WEBSITE_CODE_NOT_STARTED`, `PUBLICATION_NOT_APPROVED`, `can_ship=false`.

> **집행 의존성 보완:** Task 번호는 작성 순서이고 실제 착수 순서는 `depends_on`이 결정한다. `TSK-030`의 사용자 설계 승인/범위 확인을 마치기 전에는 `TSK-003` 앱 스캐폴딩을 시작할 수 없다.
