# G4 · 8권 공통 데이터 계약 V0.1 (연구용 설계 초안)
> 2026-10-25 · **DRAFT / NOT APPROVED**. 제3권 V0.9의 데이터·사료·지도·미디어 게이트를 8권 모두에 확장하기 위한 설계. 기존 182노드·365에지 통합 그래프나 원본 JSON을 변경하지 않는다.

## 1. 목적과 경계
지금까지 작성한 제3권 Markdown·JSON·SVG는 작업 정본이다. `data/contracts/atlas_contract_v01.json`은 향후 읽기 전용 화면·검색·지도·사상 비교용 **공통 projection 계약**이며, 강제 데이터베이스 이관이나 새로운 공개 API를 구현했다는 뜻이 아니다.

**버전·권역 구분:** VOL-01 고대교회 / VOL-02 중세교회 / VOL-03 선구자 / VOL-04 16세기 개혁 / VOL-05 가톨릭 개혁·갈등 / VOL-06 부흥·선교 / VOL-07 세계·한국 교회사 / VOL-08 사상·문헌 연계.

## 2. 변하지 않는 ID와 중복 방지
- 인물은 `PER-0001`처럼 글로벌 ID를 영속 사용한다. 후스가 제3권과 16세기 이후의 수용 서술에 등장해도 새로운 '후스 인물'을 만들지 않는다.
- `EVT`, `LOC`, `MOV`, `REL`도 글로벌 ID를 재사용한다. 원본 관계 `REL-0001` 자체를 독립 노드로 유지해 출발/대상 및 사료 연결을 보존한다.
- 역사 주장 `CLM-V03-001`, 편집본 `EDN-V03-001`, 자료 `V03-S29`, 미디어 `MAP-V03-02` 같은 **권별 접두어를 갖는 객체는 해당 권의 증거·편집 맥락을 따로 기록**한다.
- 직접 대면/사제·영향·후대 수용·신학의 일부 일치·장소 연결을 자동으로 동의어 취급하지 않는다. `textual_influence`와 `later_reception`은 직접 개인적 교류를 증명하지 않는다.

## 3. 공통 읽기 모델
| 읽기 모델 | 필수 데이터 | 화면에서 지킬 사항 |
|---|---|---|
| 인물 | 글로벌 인물 ID·권별 등장·근거·검토 상태 | 일관된 인물 ID와 여러 권의 관련 서술을 연결 |
| 연대기 | 사건 ID·`date_label`·정밀도·출처 | 대표 정렬 연도를 실제 월·일로 보여주지 않음 |
| 지도 | LOC ID·현대 좌표와 역사지리 증거의 분리 | 현대 대표 좌표를 중세 건물·전쟁 위치 복원이라고 설명하지 않음 |
| 사상 | 교리 축·주장·이견·사료 검증 등급 | 가톨릭·개신교·지역사 관점을 출처별로 구분 |
| 문헌 | 원저작·필사본·인쇄판·번역·온라인 전사·현대 논문 별도 객체 | 1844/1937 편집판·1915 번역과 중세 원본을 혼동 금지 |
| 이미지 | 자산 ID·권리·해시/설치·캡션·alt·사람 승인 | PNG 파일 존재나 SVG가 있다는 이유만으로 공개하지 않음 |

표준 projection 필수 필드: `id, type, title_ko, volume_ids, source_ids, review_status, public_visible`. 역사 날짜·검증 등급·관련 객체·이미지 고지·실제 승인 기록은 별도 필드. **정확도 `certainty`와 `review_status`는 독립**이다.

## 4. 기존 스키마에 대한 읽기 전용 어댑터
- `data/people.json`의 글로벌 인물 `name_ko`와 `data/vol03_extension.json`의 `actors`를 즉시 병합해 덮어쓰지 않는다. 둘의 ID를 검사하고 읽기 전용 뷰에서 조합한다.
- `data/events.json`의 `person_ids`와 확장 데이터의 `actor_ids`는 출처별로 다른 필드이다. 한쪽을 다른 쪽으로 변환할 때 원래 필드/출처를 보존한다.
- `data/vol03_integrated_catalog_v08.json`은 182노드·365관계의 읽기 전용 색인. 이를 '정식 DB 완성'이라고 부르지 않는다.
- AI 바이너리 6개는 `ILLUSTRATION_STAGE.json`에만 있으며 전시 불가. 지도 SVG 4점도 학술/게시 승인 전 DRAFT.
- `data/vol03_editorial_overlay_v09_p4.json`의 주장 연결·캡션·alt를 읽기 뷰에서 참조하며 원본 문장·해시를 다시 기록하지 않는다.
