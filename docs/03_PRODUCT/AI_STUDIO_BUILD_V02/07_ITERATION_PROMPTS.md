> 2026-10-25 · DRAFT. [최초 생성 프롬프트](06_MASTER_BUILD_PROMPT.md) 완료 후 **하나씩** 실행. 각 단계는 기존 코드·라우트·디자인 토큰을 보존하면서 추가한다. 성공 여부는 AI Studio 실행에서 확인해야 한다.


## 0. 어느 단계에서나 먼저 확인
**B1 최초 앱 생성 전에 [00_GITHUB_DESIGN_PREFLIGHT](00_GITHUB_DESIGN_PREFLIGHT.md)의 실제 GitHub 설계감사 `PREBUILD_GATE=PASS`가 있어야 합니다.** 파일에 접근하지 못하거나 FR18/화면14/Task36/디자인 토큰·데이터·프롬프트 사이에 BLOCKER가 있으면 개발하지 않고 보고합니다. 작업 단계가 바뀔 때 설계 계약 변경이 생기면 작은 오류부터 문서 수정·재검증 후 코드에 반영하세요.

**개요 우선/심화 증분:** 최초 콘텐츠는 `OVERVIEW`; 위클리프·얀 후스·루터 등 검증된 심층이 나중에 도착하면 **같은 ID/URL**의 `DEEP_RESEARCH` 섹션을 추가. 기존 개요 보존·미검증 연구/AI 그림 생성 금지.

**Mobile-first 동등 기능:** 320/360/375/390/430px 모바일에서 8권·검색·연대표·문헌·출처·필터가 모두 동작. 태블릿 768/1024px 및 데스크톱 1440px에서도 동일 사용성. 모바일 헤더/ESC/포커스 복귀·16px 본문·44px 터치 권장·가로 넘침 0·safe-area 확인. 실제 검사하지 못하면 NOT TESTED라고 보고합니다.


## A · 홈 디자인 미세 조정
현재 React 컴포넌트/데이터는 보존하고 Quiet Editorial Atlas 스타일로 홈을 정돈해 주세요. 레이아웃 최대폭 1200px·읽기 폭 720px, 따뜻한 오프화이트 #F7F8F5, 잉크 #1C2925, 포인트 #205F50. 섹션 사이에 넓고 고른 여백, 데스크톱 히어로 56~68px, 모바일 36~42px. 8권 카드 desktop 4열/tablet 2열/mobile 1열. 과한 그림자·유리·스톡사진·가짜 역사화·현란한 애니메이션 금지. **검증:** 320/375/768/1440px 화면/작동 메뉴, 변경 파일 요약.

## B · 역사 JSON 실제 연결
첨부된 `data/overview/` JSON 5종과 `legacy_person_crosswalk_v01.json`을 읽고 TypeScript 타입, runtime validator, 읽기 전용 selector를 만드세요. 권 8·인물 33·사건 34·문헌 20·현대 지명 22·주제 10·관계 32 및 source 23 ID를 **파일 내용 그대로** 검증하세요. 파일이 없으면 데이터가 완성됐다고 하지 말고 필요한 파일을 정확히 나열해 주세요. 발도·위클리프·후스의 OV-P/PER 정본 ID 대응, 2개 중복 별칭 출처, 11개만 링크·범위 확인한 상태 보존. **검증:** 데이터 수와 ID 고아 0, 원본 JSON 변경 0.

## C · 인물·연대표·사건
`/people`, `/people/:personId`, `/timeline`, `/events/:eventId`를 실제 JSON에 연결하고 한국어/원어명, 권 필터, 링크를 제공하세요. 인물 상세는 개요/사건/문헌/관련 인물/출처/심층준비중 순서. 사건의 `date_label` 그대로 노출, `year_start`는 정렬에만. 후스와 위클리프의 서술 관계는 문헌 영향이지 직접 만남이 아닙니다. **검증:** 33 인물·34 사건, 직접 URL·뒤로가기, 근사 연대 유지.

## D · 문헌·주제·장소·검색
`/documents`, `/documents/:documentId`, `/topics`, `/topics/:topicId`, `/places`, `/search`를 완성하세요. 문헌 20개는 원저술/번역/후대 편집본/서평을 구분하며 유료 전문 미복제. 주제 10개는 VOL-08을 통해 여러 권으로 연결. 장소 22개는 역사 지점 좌표 확인 전 **지도/핀 없음**. 검색어 루터/Martin Luther/Hus/후스/1517/성찬론과 결과 0건 시험. **검증:** 각 목록·상세, 검색/필터, 출처 메타정보.

## E · 심층 연구 블록 구조만 추가
기존 인물 ID/URL을 유지하면서 `OVERVIEW`, `DEEP_RESEARCH`, `PRIMARY_WITNESS`를 읽는 `ContentBlock` 구조를 추가하세요. 원전/학술서평/번역의 증거 수준과 `publicationStatus`를 별도 관리. **새 심층 원고를 지어내지 마세요.** 정보가 없다면 '심층 해설 준비 중'으로 유지. 테스트 fixture를 사용하는 경우 실제 역사 본문과 혼동하지 않도록 내부 코드에서만 활용. **검증:** 관련 인물 URL 변화 0, 미승인 블록 노출 0.

## F · 모바일·접근성·공개 게이트
320/375/768/1024/1440px에서 가로 넘침, 긴 한글/라틴어 제목, 단일 메뉴, 입력·링크, 포커스·skip link·reduced-motion·대비·스크린리더를 검사하세요. 별도로 PUBLIC 빌드는 명시적 승인 allowlist만 받아들이고, 현 DRAFT 개요·후보 그림·서지 전문을 HTML/JS/JSON/검색색인/정적 파일에 포함하지 않게 빌드 단계에서 검사. REVIEW_ONLY는 사용자 개인 미리보기만. **공유/Publish 실행하지 마세요.** **검증:** 수정/실패 항목 및 실제 테스트 로그.

## G · AI Studio ↔ GitHub 동기화 직전
AI Studio가 생성한 프로젝트와 원본 `worldinyj/REFORMATION-ATLAS` 사이에서 변경하려는 경로 전체 diff를 보여 주세요. 기존 `data/`, `docs/`, `assets/`, `scripts/`, `.github/`는 변경·삭제 금지. 앱 소스는 독립 기능 브랜치의 `apps/web/`에 둘 계획을 세우세요. Gemini/Firebase 불필요한 의존성, API 키, 후보 역사 이미지, 출처 미확인 전문이 들어 있지 않은지 검사. **GitHub push/merge/Cloud Run Deploy는 사용자가 검토하기 전까지 실행하지 마세요.** **검증:** 변경 목록, 충돌 가능성, 보존 경로, 브랜치.
