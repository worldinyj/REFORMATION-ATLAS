## 0. 제품 수용 조건 강화: Prebuild-GitHub / Overview-to-Depth / Mobile parity
1. **개발 전:** AI Studio가 실제 GitHub 설계 브랜치에서 PROJECT PLAN·PRD·TRD·UXUI·TASKLIST·토큰·14개 화면 계약·두 언어 06/07 프롬프트·개요 JSON을 읽어 일관성/연결성/통일성을 점검한다. 요구 18·화면 14·Task 36(33 P0/3 P1), 정본/임시 ID·권 8·출처·공개 상태 모순을 기록하고 필요시 승인된 설계파일만 최소 수정·재검증한다. `PREBUILD_GATE=PASS`가 없거나 접근할 수 없으면 앱 생성 금지.
2. **콘텐츠 성장:** 최초 P0는 `OVERVIEW` 기반. 뒤에 위클리프·얀 후스·루터 등 각 인물·사건·문헌의 심층 자료를 만들면 기존 개요에 `DEEP_RESEARCH` 섹션을 추가하고 canonical ID/URL/출처·개정 이력을 유지한다. 심층 연구 완료까지 초기 UI를 기다리거나 전체 페이지를 새로 만들지 않는다.
3. **모바일 동등 핵심 기능:** 320/360/375/390/430px에서 홈→권→인물/사건→문헌, 연대표, 검색, 원문/번역 구분, 출처 표기가 모두 사용 가능해야 한다. 1열 카드/20px 여백, 16px 이상 본문, 긴 원어명 줄바꿈, 스크린리더/키보드 메뉴, 약 44px 이상의 터치 목표, 가로 넘침 0. 768/1024px 태블릿·1440px 데스크톱과 동일 정보 접근.
4. **수용 증빙:** 설계 감사표·수정 diff/테스트, 모바일 각 폭 화면 QA 및 브라우저(iOS Safari/Android Chrome) 실행 여부, 심층 블록을 더한 뒤 URL·관계 링크 불변 테스트. 테스트하지 않은 항목은 PASS라 주장하지 않는다.
5. **공개/저작권:** 미승인 DRAFT 개요·AI 그림/지도·유료 원전 전문은 PUBLIC 번들에 포함되지 않는다. 개인 프리뷰·공용 사이트의 데이터 경계는 별도 검증한다.


## A. 제품 정의
세계와 한국 교회사의 흐름을 8권과 관련 인물·사건·문헌·사상으로 연결해 설명하는 지식 탐색 웹앱. **예쁜 사이트보다 '역사의 맥락을 발견하게 하는 사이트'**가 목표.

### 첫 사용자 경험
1. 홈에서 웹앱의 목적과 8권 목차를 한눈에 이해.
2. 권 하나를 누르면 시대 개요와 핵심 인물·사건 목록으로 진입.
3. 인물 상세에서 사건·원전 소개·연관 주제로 이동.
4. 연대표에서 동일한 사건을 다른 시대와 비교.
5. 출처 표기를 보고 해당 해설이 '개요/번역/학술 연구' 어느 수준인지 알 수 있음.

## B. 성공 기준(내부 시범)
- 홈과 VOL-01~VOL-08 **8권** 화면이 정상 동작. 제8권은 시대가 아니라 **사상·문헌 아카이브**.
- 개요 데이터: **33 인물 / 34 사건 / 20 문헌 / 10 주제 / 22 텍스트 장소 / 32 관계**를 테스트용 **비공개 내부 검토 화면**에서 검색·연결 가능.
- 검색: `루터`, `Martin Luther`, `Hus`, `후스`, `1517`, `성찬론`의 동작을 검증.
- 모바일 320/375px, 태블릿 768px, 데스크톱 1440px의 읽기·탐색 품질.
- 미검증 위치의 지도 핀 **0**, 미승인 인물화·AI 그림 공개 **0**, 공개 빌드의 DRAFT 원고 **0**.
- 별칭 3명(발도·위클리프·후스) 기존 `PER` ID에 정합하게 매핑.
- 내용 업데이트 시 인물 URL/ID 유지. **웹페이지를 다시 만들지 않고 콘텐츠만 심화** 가능.

## E. 디자인 요구사항 (사용자 요청 반영)
**스타일:** 여백이 넉넉한 contemporary editorial museum + 2026 web minimalism. 고전적인 역사 주제를 다루지만 화면은 **2026년의 세련된 현대 웹앱**으로 만든다.
- 큰 헤드라인 + 작고 규칙적인 문단·메타정보. 데스크톱 hero H1 56~68px, 모바일 36~42px.
- 배경 warm-off-white, 본문 ink, 강조 forest. **일관된 1개 강조색**, 너무 많은 테마색·그라디언트 없음.
- 콘텐츠 최대폭 1200px, 본문 폭 720px 내외. 넉넉한 상하 여백: 섹션 80~120px desktop / 48~64px mobile.
- 카드 높이 고정하지 않음, 얇은 보더, 그림자 최소화, 작은 micro-interaction 120~200ms, reduced-motion 존중.
- 커버 사진·기성 역사인물 이미지를 억지로 배치하지 않음. 초기에 타이포/연대표/숫자보다 **콘텐츠·텍스트** 중심.
- 모바일 햄버거 메뉴, 빠른 검색, 분명한 현재 위치. 항상 '글 읽는 앱'처럼 느껴져야 함.
- 첫 화면: **상단 내비 → 타이포그래픽 히어로 → 8권 4×2 그리드(모바일 1열) → '역사를 탐색하는 세 가지 방법' → 대표 연대 흐름 → 출처 방식**.
- 출처·자료 상태는 작지만 읽기 편한 텍스트 형태. 채도가 강한 배지 사용 금지.

## F. 비기능 요구
- WCAG 2.2 AA 목표 (자동검사+수동 키보드·스크린리더 시험).
- 실제 모바일 장치에서 레이아웃 깨짐·가로 스크롤 0.
- 테스트 환경 기준 LCP 2.5초 이하 지향, 필터/검색 즉각적 반응.
- 오프라인 정적 자료만으로도 목록/연대표/문헌 탐색 가능하도록 설계.
- AI Studio에서 생성된 코드는 GitHub로 버전 관리, 최초 생성 후 바로 검사 가능.
- API KEY를 필요하지 않은 MVP에 넣지 않는다. AI API 기능 추가시 서버 측 Secrets 이용.

## G. 권리·출처·공개 필수
- 현재 전체 개요는 **DRAFT**. AI Studio가 생성한 사이트가 보이더라도 즉시 공유·Publish하지 않는다.
- 전문을 확인하지 않은 자료는 '원문 검증 완료'라고 표시하지 않는다.
- 실물 지도 좌표·중세 건축·AI 초상의 역사적 고증은 별도의 자료/권리 게이트.
- 공개 서비스엔 **명시적으로 publication_approved** 된 데이터만 들어가야 한다. `noindex`만으로 비공개를 보호하지 않는다.

## H. 배포·수용 결정
최초 앱은 개인 미리보기용 **개발 산출물**이다. 사용자가 UI/정보구조/권리 범위를 검수한 뒤에만 Cloud Run 등 실제 배포 경로를 결정한다. Firebase Auth/Firestore는 데이터 편집·로그인 요구가 생기기 전 필수가 아니다.
