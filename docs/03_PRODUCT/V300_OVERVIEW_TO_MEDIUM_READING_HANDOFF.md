## 잘못된 연결을 막는 사례

- OV-P-001: 안디옥의 이그나티우스와 로욜라의 이냐시오는 다른 인물.
- OV-D-005: 후스와 위클리프의 동명 교회론은 다른 저작.
- OV-E-019: 1530년 신앙고백 제출과 1555년 화의는 다른 사건.
- OV-E-020: 1536년 초판 사건과 1559년판을 구분.
- OV-E-014: 1433~1436년 콤팍타타와 16세기 바젤 개혁을 구분.

## 호출 예시

```js
import {createMediumAtlas} from '../../integrations/medium-atlas-v298/adapter.mjs';
import {createOverviewReadingBridge} from '../../integrations/overview-readings-v300/bridge.mjs';

const atlas = createMediumAtlas(delivery);
const bridge = createOverviewReadingBridge(crosswalk, atlas);
const initial = bridge.resolve('OV-D-012'); // 1536년 초판을 우선
const extended = bridge.resolve('OV-D-012', {includeRelated: true}); // 1559년판 추가
const missing = bridge.resolve('OV-P-024'); // 웨슬리: 직접 원고 없음
```

`delivery`는 기존 V2.97 전달본 객체, `crosswalk`는 `data/contracts/atlas_v300_overview_medium_reading_crosswalk.json` 객체다. 이 모듈은 fetch나 앱 상태 변경을 하지 않는다. 결과의 `readers[].id`로 V2.98의 `getReader()`를 호출한다. 이 ID를 실제 앱의 라우트나 개요 ID와 같다고 처리하지 않는다.

개요 항목의 상태가 일부 범위 또는 배경 자료이면 `scope` 안내를 함께 표시한다. 대응 원고가 없을 때 다른 원고로 자동 대체하지 않는다. 역방향 `forReader(readerId)`는 읽기 탐색용 연결이며 영향 관계나 직접 참석의 증거가 아니다.


생성기는 원래 개요 ID·제목·레코드와 입력 체크섬, 435편 ID 참조, 배경·후속 역할, 잘못된 연결 배제 규칙을 검사한다. 원본 개요·본문은 수정하지 않는다. 노드 검사는 기본/후속 조회와 없는 항목 처리, 역방향 연결, 오류 입력을 검사한다.

## 계획 대비 드러난 공백

435편의 전체 수와 기존 개요의 충족 범위는 다르다. 고대·중세 일부·후대 부흥·한국 교회사에는 직접 연결할 원고가 남아 있지 않으며 표에서 확인할 수 있다. 이 공백은 앱의 검색 오류가 아니라 현재 집필 범위의 차이다. 다음 집필의 우선순위를 이 표의 직접 원고 없음 항목에서 정할 수 있다.

실제 AI Studio 앱의 개요 ID와 구조가 이 저장소 스냅샷과 같은지는 아직 확인하지 않았다. 실제 앱에 적용하기 전에 그 데이터를 대조해야 한다. 별도 검토 화면이 열려 있다는 사실과 실앱 탑재는 구분한다. main·기존 원고·실제 앱을 보존하고 공개 보류를 유지한다.
