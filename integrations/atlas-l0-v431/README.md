# 종교개혁 ATLAS V4.31 — 기존 Google AI Studio React 웹앱에 이식할 비공개 L0 컴포넌트

> **상태:** React 인터페이스 후보 제작·별도 실제 브라우저 검증 진행. 기존 Google AI Studio Build 앱의 소스·프로젝트 ID·스테이징은 이 저장소에 없으며 **직접 수정하지 않았다**. 기존 `main` 및 연구 원고 불변. `can_ship=false`.

## 왜 V4.31인가

V4.29에는 독자용 역사 원문 8권, 비교 6주제, 연결 42개, 입문 원고 6장면이 있다. V4.30은 데이터 정합성과 검색·라우트 API를 검증했지만 **React 웹앱에 그대로 삽입할 화면 구성요소는 아직 없었다**. V4.31은 이 간극을 메운다.

- [AtlasL0Panel.jsx](./AtlasL0Panel.jsx): 8권/6주제/입문 보기, 실제 원고 페이지, 주제↔권 이동, 입문 이전/다음, 한국어 전체 검색
- [atlas-l0.css](./atlas-l0.css): 타 앱 디자인에 영향을 적게 주도록 `atlas-l0-` 범위로 제한한 스타일. 320px부터 2열 카드를 1열로 전환
- [V4.30 읽기 전용 브리지](../atlas-l0-v430/bridge.mjs): V4.29의 20개 실제 텍스트와 42개 링크를 구조 검증 후 전달
- [V4.29 본문 JSON](../../handoff/V429_AI_STUDIO_PRIVATE_L0_CONTENT_IMPORT.json): 검증된 원본 텍스트를 수정 없이 전달
- [demo-entry.jsx](./demo-entry.jsx), [demo.html](./demo.html): CI 안의 **localhost 전용** React 시험 입력. 이 파일의 정적 JSON import 방식을 실제 공개 앱에 그대로 복사하지 말 것

### 콘텐츠 범위

제1~7권은 시대 구분이지만 **VOL-08은 별도의 시대가 아니라 여섯 관점을 가로지르는 비교 자료**다. 주제와 일곱 역사권 사이에는 42개 ID 참조가 있으나 깊이 있는 513개 원고의 실 URL이라고 가장하지 않는다. 고대와 아시아·아프리카·한국의 역사를 16세기 유럽의 시작 이후로만 귀속시키지 않는다. 이 단계에서 추가 역사 서술을 AI가 임의 작성하지 않는다.

현재 V4.29 본문에는 단락·제목(##, ###)·인라인 굵게 강조·인용문이 있다. React 화면에서는 **raw HTML이나 `dangerouslySetInnerHTML` 없이** 이 제한된 범위의 마크다운을 텍스트/시맨틱 요소로 표현한다. 외부 이미지·원전 영인·미허가 현대번역은 추가하지 않는다.

## 기존 AI Studio 앱에서의 구체적인 적용 경계

**1. 앱을 기존 상태로 보존**한다. 앱의 현 라우터와 CSS, 폴더 구조를 먼저 확인한 뒤 **복제한 비공개 개발 버전**에만 적용한다. 현재 소스가 없으므로 `App.tsx`, `routes.tsx` 등의 파일을 수정했다고 주장하지 않는다.

**2. 보호된 L0 콘텐츠 로더가 먼저 있어야 한다.** 원고 JSON을 공개 React 번들에 직접 임포트하거나 정적 공개 URL에 배치하면 '비공개 표시'만으로 콘텐츠 접근을 제한할 수 없다. 앱의 인증·권한을 처리하는 호스트 서버에서 접근을 실제로 제한하고, 승인된 스테이징 사용자에게만 원고 객체를 전달해야 한다. UI의 `stagingGranted={true}`는 서버 인증 자체가 아니다.

**3. 앱 소스 경로에 맞춰** 이 파일의 `import {createAtlasL0ReadOnlyBridge} from "../atlas-l0-v430/bridge.mjs";`를 실제 상대경로로 바꾼다. React 패키지 버전·bundler/TS 설정은 **실제 앱의 기존 값 유지**, 불필요한 의존성 신규 설치는 지양한다. 단위시험은 React 19 환경에서 검증되지만 앱 자체의 React 버전 일치 보증은 아니다.

**4. 호스트 전용 사용자 페이지**에 승인된 `payload`와 검증 완료 신호를 `<AtlasL0Panel payload={payload} stagingGranted={true}/>`로 전달한다. 비인가 사용자에게는 원고 객체와 번들/응답 모두 접근시키지 않는다. 기존 앱의 URL 패턴은 추정하지 않고, 현재 라우팅 규칙을 사용한다.

**5. 통합 후 다시 검증**한다. React 컴포넌트 자체의 브라우저 PASS는 별도 앱의 인증·네비게이션·배포 승인을 대신하지 않는다. 실제 AI Studio 스테이징에서 권별 본문·주제 연결·검색·320px 화면·키보드 동작·뒤로가기·오류페이지·접근 권한을 확인해야 한다.

## 재현 가능한 V4.31 검증과 그 한계

CI는 **React 19 / esbuild / Chromium / WebKit**을 임시 환경에 설치해 localhost에서 모듈과 실제 V4.29 원고를 연결한다. 데스크톱 1440px, 모바일 375px·320px, 8권/6주제/6장면, 실제 주제→권 이동, 굵게 강조, 전체 검색, 검색어 삭제, 비공개 UI 차단을 시험한다. JSON의 Git blob SHA와 컴포넌트 소스 SHA를 먼저 확인한다. 통과할 때만 PASS를 기록하며 실제 브라우저 PNG를 연구 브랜치에 보존한다.

**실제 Google AI Studio 앱에서 수행된 검증은 0건.** 학술 전문가 검토 0명, 실제 독자 0명, 별도 앱 호스트 인증 검증 0건, 외부 공개 승인 0건이다. `can_ship=false`.

앱이 별도 AI Studio Build에만 있다면 공식 기능으로 코드 ZIP을 내보내거나 GitHub와 연결할 수 있다. 이 단계에서 필요한 것은 **실제 앱 소스(또는 별도 앱 GitHub 저장소)**이며, 사용자에게 연구 저장소 main의 내용이나 앱의 과거 결과를 덮어쓰게 요구하지 않는다.
