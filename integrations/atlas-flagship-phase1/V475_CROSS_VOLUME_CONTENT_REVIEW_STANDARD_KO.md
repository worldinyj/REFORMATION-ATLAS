# 종교개혁 ATLAS — V4.75 다른 권에도 적용할 콘텐츠·검토 공통 계약

**목적:** 제4권의 검증된 기술 구조를 다른 권의 콘텐츠 작성/검토 워크플로에 재사용한다. 새로운 권의 역사 사실을 제4권 원고로 대체하지 않는다.

## 1. 연구 콘텐츠의 층위

| 층위 | 필수 항목 | 문헌 정확성 조건 | 실제 사용자 경험 |
| --- | --- | --- | --- |
| 신원 | `project, volumeId, chapterId, sceneId` | 각 권·장·사건에 고유 식별자 | 해당 권으로 복귀 가능 |
| L0 | `title, markdown, sourceRefs` | 일반 독자가 이해할 수 있는 범위 안에서 과장 방지 | 개요부터 입장 |
| L1 | `title, markdown, sourceRefs` | 판본·필사본·당대 인쇄·후대 번역 관계 정확히 구별 | 심화 읽기 |
| 시간 | `timeline[].id/year/claimLimit/sourceRefs` | 사건의 날짜와 인쇄 판본 연도 구분 | 연표로 탐색 |
| 사료 | `sources[].id/sourceKind/url/sourceLimit/eventIds` | URL, 자료 종류, 증거 능력과 미해결 사항 | 카드에서 실제 원본 링크 |
| 이본·쟁점 | `comparisons[].sourceId/observation/limitation` | 확인한 차이와 추정 계보를 혼동하지 않음 | 비교표 |
| 전문가 | `expertReview.claims[]` | 고위험 주장 독립 2인 검토, 미확인 사항 HOLD | 전문가의 근거 확인 |
| 독자 | `participant.tasks/questions` | 정답은 참가자 공개 자료에서 제외 | 익명·자발적 과제 평가 |
| 출시 | `releaseGate` | 전문성·독자 이해·권리·접근통제 조건 모두 필요 | 승인 전 연구용에 한정 |

모든 권은 이러한 **같은 필드와 게이트 구조**를 사용하되, 권마다 독자적인 사건·문화·원어·사료를 편집한다. `ATLAS_REVIEW_BUNDLE_V1`은 동일한 4개 사건이나 6개 출처를 강요하지 않는 재사용 규격이다.

## 2. 필수 검증 알고리즘

[공통 검증 모듈](./atlas-review-bundle-contract.mjs)의 `validateAtlasReviewBundle(bundle)`은 다음을 검증한다.

- 권·장·사건 ID가 존재하고, L0와 L1을 모두 포함하며 연결한 사료 ID가 등록되어 있는가?
- 모든 사건, 사료, 주장, 질문 식별자가 중복되지 않는가?
- 출처에 HTTPS와 사료 유형·한계가 기록되었는가?
- 전문가 주장은 실제 검토 전에는 항상 `PENDING`·`expertApproved=false`인가? HIGH 2인?
- 독자에게 제공되는 데이터에는 평가 정답·오해코드가 없는가?
- 실제 전문가/독자 수행이 없다는 기록과 출시 차단 조건이 그대로 유지되는가?

**유의:** 현재 검증 모듈은 사전 검토용 **닫힌 상태만 유효**하다고 판단하는 연구용 계약이다. 나중에 실제 전문가 검토가 이뤄졌다고 자동으로 `canShip=true`를 바꾸는 승인 시스템이 아니다.

## 3. 제4권 시범 기준 데이터

- 공통 예시: [`ATLAS_V475_CROSS_VOLUME_REVIEW_BUNDLE.json`](../../research/data/ATLAS_V475_CROSS_VOLUME_REVIEW_BUNDLE.json)
- V4.72 L0 3문단·L1 6절, 사건 4개(1529·1530·1531·1540), 사료 6종, 문헌 비교 3건
- 기존 V4.57 연구 주장 14건 중 HIGH 10건 / 필요한 2인 독립 검토; 독자 TASK 3개·Q 9개
- **독자 Q09**는 구형 “첫 화면 두 자료” 대신 현행의 **“여러 사료 카드”** 기준으로 문구를 업데이트했다. 원본 V4.57 평가도구는 보존했으며 정답을 이 번들에 다시 출판하지 않았다.

## 4. 다른 권으로 확대할 때의 순서

1. 새 권의 개요 L0와 중급 L1을 **해당 권 자체의 사료**로 작성하고 사건/자료 고유 ID를 부여한다.
2. 사료마다 **원본 인쇄면, 보관소 목록, 후대 학술 편집, 역사학적 해석**의 근거 종류와 검증 한계를 기록한다.
3. 쟁점별 역사 주장을 HIGH/MEDIUM/LOW로 검토하고 미확정 자료는 HOLD한다.
4. 전문가용 양식과 **정답 미포함 독자 평가**를 별도로 생성한다. 퀴즈 문항은 해당 권 내용에 따라 새로 만들고 기존 제4권 정답을 재활용하지 않는다.
5. 사람 검토, 저작권, 서버 인증·개인정보 처리 조건까지 실제 확인하기 전에는 운영 서비스로 승격하지 않는다.

## 5. 보안·윤리와 릴리스

- 공개 GitHub에 있는 기존 V4.57 파일에는 정답이 있으므로 **공개 URL만으로 눈가림(blind) 검사를 구현할 수 없다.** 실제 운영 시 정답을 접근제어된 별도 환경에서 관리하고, 참가자에게는 별도 고정된 안내/설문 화면만 제공해야 한다.
- [독자 평가용 인쇄 기록지](./V475_READER_PILOT_WORKSHEET.html)는 스크립트·외부 요청·전송 기능이 없는 파일이다. 페이지 내 선택은 로컬 화면/출력 용도이고 어떤 응답도 수집하지 않는다.
- HTML 파일을 GitHub에서 단순히 누르는 것은 호스팅된 평가 페이지와 다르므로 **다운로드해서 오프라인으로 열어야 한다.**
- 외부 기관 메시지, 전문가 초청, 유료 주문, 실제 독자 모집은 하지 않았다.

**게이트:** `can_ship=false`, `can_merge_main=false`, `can_import_ai_studio=false` 유지. `main`과 실제 AI Studio 앱 변경 없음.
